# X MCP：10分钟关注200人？先看真实边界

> 6 页 | Windows SAPI | 真实数据边界版

## THE HOOK
**10 分钟关注 200 人？**

十分钟关注两百人，这是一个很抓眼球的产品噱头。但我们不能把点击速度直接说成成功率。真实小样本里，关注周期的中位数约为一点一六秒；另一轮十八次连续关注，按钮全部变成 Following，可是服务端最终确认的只有八次。这个视频会把速度和边界一起展示。

## THE PRODUCT
**我们做的不是脚本，而是一层 MCP**

我们的产品不是一段只会点击的脚本，而是一层 MCP。Agent 先理解任务，系统再把任务拆成有顺序的动作。大任务可以分块，每块独立确认。内置浏览器可以执行，外部 Agent 也可以领取一个动作、自己操作，再返回证据。两条路径共用同一套租约和后置验证。

## MEASURED
**数据：协议快，真实 X 慢**

从数据看，协议层很快。五百一十二个本地客户端的 HTTP mock 达到九百九十四 RPS，二千零四十八客户端的极限观察仍然零错误，但吞吐降到五百三十三 RPS。真实 X profile 冷读约一点三到一点六秒，快速时间线读取则收到过四二九。真实工作流的瓶颈，是浏览器和外部服务，不是 MCP 消息本身。

## COST
**成本：浏览器路径不花 X API 费**

成本要分开算。浏览器路径没有使用 X API credits，但它消耗机器时间、浏览器资源和模型上下文。模型费用取决于 Agent 主机，本轮探针没有调用模型，所以没有虚报 token 成本。作为 API 参考，如果每次写入零点零一五美元的已知假设适用，二百次下限约三美元；实际还要加读取、重试和限流处理。

## HONEST LIMITS
**不能宣传的三句话**

所以宣传时有三句话不能说。不能说二百个关注已经在十分钟内真实完成；不能说按钮变成 Following 就等于服务端成功；也不能说页面级并行一定更快。现在我们已经把大批次接口做成四百一十个操作、默认每块二十个，但真实两百关注仍需要 follow 工具、服务端复核和分阶段验收。

## CALL TO ACTION
**把噱头变成可验证产品**

这就是 X MCP 的核心价值：让 Agent 可以连接 X，但不把外部写入变成黑箱。先运行无凭据的本地 demo，再让自己的 Agent 领取一个分块动作，最后提交结果和证据。我们的宣传可以用十分钟关注两百人的问题吸引注意，但真正要卖的，是可分块、可确认、可验证、可恢复的 Agent 社交执行层。
