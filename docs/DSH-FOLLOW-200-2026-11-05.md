# DSH + DeepSeek follow test: 200 verified follows

Status: **verified**. 200 unique handles reached `state=following` through
batches that a DSH run proposed and executed with a DeepSeek model.

The number counts only rows that satisfy all four ledger conditions:
`status=completed`, `result.changed=true`, `result.verified=true`,
`result.state=following`. Already-following profiles are excluded, and no
uncertain handle was retried.

## Time coverage

Every action has a duration.

- 202 of 202 verified follows store `result.elapsed_seconds`.
- 100 of 100 uncertain actions have a derived duration from `claimed_at` to
  `completed_at`; median 37.0 s.
- No finished action is missing both values.

The ledger only stores `attempt_elapsed_seconds` for a subset of uncertain
rows. The audit reads the claim and completion stamps instead of rewriting
history.

## What failed, and why

```text
finished DSH rows 302
  verified         202   66.9%
  uncertain        100   33.1%
    ACTION_UNCERTAIN        86
    BROWSER_RUNTIME_MISSING 10
    X_RATE_LIMITED           4  (3 real 429, 1 blocked by our own counter)
uncertain rows with visual fallback  74
```

`ACTION_UNCERTAIN` means the write was dispatched and the follow state could
not be proven after reload. The run policy is to stop that handle and leave it
final. That is a proof gap, not a silent success.

## Defect found and fixed

The bounded operator window spent a slot before the action ran, so the action's
own re-check rejected the last action of every window. The window now records
claimed action ids and admits only those at the limit.

Live confirmation: the waves run after the fix finished 15/15 and 14/14 with
the final action verified.

## Audit command

```powershell
python -X utf8 tools/dsh_follow_audit.py `
  --state-dir C:\Users\<you>\AppData\Local\x-starter\demo-state\<ledger> `
  --runs D:\workspace\agent-help\releases\demos
```

The audit prints one JSON object. It attributes a batch to DSH only when the
batch id appears in that run's `agent.jsonl`, and reads the model from
`install.patch.yml`.

## Limits

- The 15-per-window figure applies to the follow endpoint. Likes, reposts and
  replies have separate counters that this test did not measure.
- The number is one account on one network path. It does not establish a
  platform-wide quota.
- A verified following is a current-state check. It does not measure whether
  the other account follows back.
