## E 架构

```flow
MCP 客户端 -> 协议层 -> 业务规则 -> 动作队列 -> 浏览器执行器
协议层 -> 会话隔离
动作队列 -> 确认与租约
动作队列 -> 证据链
浏览器执行器 -> DOM 优先
浏览器执行器 -> 视觉兜底
```

每层可独立替换。浏览器执行器换成官方 API 时，上层不用改。

## F 写入怎么保证不失控

```sequence
Agent -> 服务端: 准备动作
服务端 --> Agent: 返回确认短语
Agent -> 服务端: 提交确认短语
服务端 -> 队列: 发放单次租约
队列 -> 浏览器: 执行一次
浏览器 --> 队列: 页面状态
队列 --> Agent: 复验结果
```

四道闸门：

1. 确认短语由服务端生成，Agent 不能自己编。
2. 每个动作单独租约，用一次就失效。
3. 读操作的凭证不能用来写。
4. 状态不明时标记为不确定，不自动重试。

## G 接入只要三步

```bash
tester.cmd setup     # 装依赖
tester.cmd smoke     # 自检
tester.cmd config    # 生成 MCP 配置
```

把生成的配置粘进任意支持 MCP 的客户端就能用。

需要 Python 3.11 或更高版本，以及 Chrome。不需要 X API Key。

## I 为什么值得用

```callout info 三个差异点
写入有确认链，不是裸接口。

```

## J 成本和兜底

X MCP 自托管时不收取 MCP 调用费。用户承担 Agent 模型、机器、浏览器和网络成本。

| 路径 | X API credits | 运行成本 |
|---|---|---|
| 公共读取 | 0 | Agent 和网络 |
| 浏览器路径 | 0 | Agent、浏览器和机器 |
| X API 路径 | 按官方当前消费计费 | Agent 和网络 |
| 托管浏览器 | 取决于服务商 | 浏览器会话和模型 |

浏览器路径是正式兜底。产品不会把 API 当成唯一入口。第三方 MCP 可以提供搜索、内容和通用浏览器能力，X MCP 继续负责确认、租约、执行、复验和证据。

### 200 个关注

| 路径 | X API credits | 已测时间口径 |
|---|---:|---|
| 自托管浏览器 | 0 | 约 50–110 分钟 |
| X API | 约 `$3.00` 的 Follow 请求估算 | 取决于官方限额和接口响应 |
| X API + 200 个逐项用户读取 | 约 `$5.00` 的请求估算 | 读取和 Follow 分开计费 |

API 数字使用官方价格页的 `User Interaction: Create` `$0.015`/request 和 `User: Read` `$0.010`/resource 计算。Follow 是否归入该计费分类，应在 Developer Console 中确认。Agent 模型、主机、浏览器和网络费用另计。
